# UltiTrack

Система компьютерного зрения для трекинга игроков в зальном алтимат-фрисби с проекцией координат на 2D-радар.

## Возможности
- **Детекция и трекинг игроков**: кастомная модель **YOLOv11** + ByteTrack + фильтр Калмана и венгерский алгоритм для удержания 10 слотов игроков на поле.
- **Разделение команд 5×5**: проверка стартовых линий эндзон, а при их отсутствии — цвет торса в Lab, k-means и венгерский алгоритм с жёстким балансом 5+5; команда и уверенность попадают в телеметрию и на радар.
- **Тактический 2D-радар**: отрисовка перемещений игроков поверх видео в реальном времени.
- **15-секундные 2D-повторы**: вырезание окна из телеметрии, оффлайн-сглаживание и standalone HTML-плеер для OBS.
- **Командные и персональные тепловые карты**: PNG-карты плотности позиций команд A/B и каждого игрока по `telemetry_*.json`.
- **Экспорт данных**: сохранение телеметрии поинта и логов для последующего анализа (`data/processed/`).

## Установка и подготовка

В проекте используется пакетный менеджер **[uv](https://astral.sh)**.

### 1. Клонирование и установка зависимостей
```bash
git clone git@github.com:AntonNaibauer/UltiTrack.git
cd UltiTrack
uv sync
```

### 2. Добавление весов модели
В репозитории не хранятся файлы весов нейросети (`.pt`). Для работы проекта используются веса кастомной модели, обученной на базе **YOLOv11** (классы: `0 — disc`, `1 — player`).

1. Создайте папку `models/` в корне проекта (если её нет).
2. Поместите туда файл весов:
   ```text
   models/ulti_indoor_with_disk_v3.pt
   ```
*(При необходимости имя файла можно изменить в `src/ultitrack/config.py` в переменной `MODEL_NAME`).*

### 3. Подготовка видео и калибровки
1. Поместите исходное видео матча в папку `data/raw/` (по умолчанию в `main.py` указан файл `match7.mp4`).
2. Убедитесь, что в папке `calib/` присутствуют файлы калибровки (`court_points.json`, `lens.json`, `homography.json`). Если калибровки ещё нет, при первом запуске откроется интерактивное окно для разметки точек поля.
3. При переносе на другой зал отредактируйте `calib/venue.json`: размеры поля, длину эндзон и отступы стен у линии. Код при этом менять не нужно.

## Запуск

Запустите основной пайплайн обработки видео через `uv`:

```bash
uv run python -m ultitrack.main
```

### Результаты работы
После завершения обработки в папке `data/processed/` появятся:
- `tracked_<имя_видео>.mp4` — видео с боксами игроков и 2D-радаром в левом нижнем углу;
- `telemetry_<имя_видео>.json` — покадровые 2D-координаты игроков в метрах (schema v2: все 10 слотов с полями `status`, `team`, `team_conf`, `vx/vy`);
- `review_<имя_видео>.json` — лог подозрительных кадров для ручной проверки.

### Классификатор команд
После первых ~1.5 секунд поинта (`TEAM_CALIBRATION_SECONDS`) слоты раскладываются ровно на 5+5. Сначала проверяется стартовая расстановка: если на первом кадре 5 игроков стоят на одной линии эндзоны, а 5 — на другой, команды берутся из геометрии линий. Это исправляет выбросы цветового классификатора (белые/тёмные майки, блики, судьи в кадре). Если линии не найдены — fallback на k-means по Lab-признаку торса и венгерский алгоритм с балансом. Дополнительно в тесных парах слотов (< 4 м) прямой матч по ByteTrack ID проверяется по цветовому эталону слота: при конфликте решение принимает венгерский алгоритм с цветовым штрафом. В «куче» (< 2.5 м) смена tracker_id слоту запрещена: он временно уходит в coast, чтобы не обменяться игроками и командами. До калибровки в телеметрии `team = null`, `team_conf = 0`, а фишки остаются нейтральными. Отключить классификатор можно флагом:

```bash
uv run python -m ultitrack.main match7.mp4 --no-team-classifier
```

### 2D-повтор на 15 секунд
```bash
uv run python -m ultitrack.replay \
  --telemetry data/processed/telemetry_match7.json \
  --start 120 --duration 15 \
  --out data/processed/replay_match7_120.html
```

Получится standalone HTML без внешних зависимостей: поле, фишки команд, номера слотов, хвосты, диск, play/pause, scrubber и режим «прозрачный фон» для OBS (или `?transparent=1` в URL). Для сглаживания используется Savitzky–Golay по всему 15-секундному окну; отключить — `--no-smooth`.

### Потерянные игроки
Если слот потерян, радиус поиска постепенно расширяется до 9 м — это позволяет быстро вернуть игрока после рывка, а не ждать respawn. При возврате слот сверяется с цветовым эталоном и не привязывается к игроку другой команды. На радаре потерянный/coasting слот остаётся приглушённым цветом своей команды, а не безымянно-серым.

### Тепловые карты команд и игроков
```bash
uv run python -m ultitrack.analytics.heatmaps data/processed/telemetry_match7.json
```

По умолчанию PNG сохраняются в `data/processed/heatmaps/`:

- командные: `heatmap_<stem>_team_A.png`, `heatmap_<stem>_team_B.png` (и `team_unknown.png`, если есть), общая `heatmap_<stem>_combined.png`;
- персональные: `heatmap_<stem>_player_<NN>_team_<T>.png` для каждого слота с active-точками, мозаики `heatmap_<stem>_players_team_<T>.png` (5 карт в ряд) и общая `heatmap_<stem>_players_combined.png`.

Игрок определяется стабильным `id` слота из telemetry v2 (1..10), а не номером на майке: `Player 3` — это слот 3 на протяжении поинта. Команда в шапке карты берётся большинством голосов по кадрам слота, поэтому до калибровки точки не теряются. Параметры сетки: `--bin-size 0.5`, `--sigma 0.6`; только командные карты — `--no-players`; раскладка мозаики — `--player-columns`.

## Структура проекта

```text
UltiTrack/
├── calib/                  # Калибровка камеры, разметка поля и профиль зала (venue.json)
├── data/
│   ├── raw/                # Исходные видеозаписи
│   └── processed/          # Готовые видео, телеметрия и логи
├── models/                 # Веса обученной модели YOLOv11 (.pt)
├── src/ultitrack/          # Основной исходный код
│   ├── analytics/          # Оффлайн-аналитика (тепловые карты)
│   ├── config.py           # Пути, пороги, профиль зала и параметры радара
│   ├── court_mapper.py     # Гомография и перевод пикселей в метры
│   ├── detector.py         # Обёртка над YOLOv11 и ByteTrack
│   ├── lens.py             # Модель радиальной дисторсии
│   ├── main.py             # Точка входа (основной пайплайн)
│   ├── radar.py            # Отрисовка 2D-радара
│   ├── replay.py           # 15-секундный повтор и HTML-плеер
│   ├── roster_tracker.py   # Трекинг 10 слотов игроков (Калман + матчинг)
│   └── team_classifier.py  # Классификация команд 5×5 по цвету торса
└── tools/                  # Вспомогательные скрипты калибровки и анализа
```
